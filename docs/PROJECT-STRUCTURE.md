# Структура frontend ЦГБ №3

Проект разделён на публикуемые файлы, документацию, SQL текущей версии, конфигурацию развёртывания, инструменты проверки и архив. Nginx не должен отдавать наружу весь репозиторий: его `root` направляется только на каталог `public`.

## Каталоги

- `public/*.html` — рабочие страницы. Плоское расположение сохраняет существующие адреса и не требует менять пользовательскую навигацию.
- `public/assets/css` — стили сайта и редактора документов.
- `public/assets/js/core` — асинхронное ядро, конфигурация, загрузчик источника данных, авторизация и роли.
- `public/assets/js/ui` — общий интерфейс, навигация, поиск, настройки, звук и уведомления.
- `public/assets/js/utils` — независимые вспомогательные модули.
- `public/assets/js/features` — бизнес-логика конкретных разделов.
- `public/assets/vendor` — зафиксированные сторонние браузерные библиотеки.
- `public/assets/images` — изображения по назначению: `brand`, `teams`, `autopark`.
- `public/assets/ustav` и `public/assets/map.*` — совместимые публичные пути материалов устава и карты; они сохранены, потому что эти URL могут находиться в данных и внешних ссылках.
- `public/assets/uploads` — статические загруженные материалы, если они входят в репозиторий.
- `database/legacy-supabase` — SQL только для текущей Supabase-версии. Он не публикуется Nginx.
- `deploy/nginx` — конфигурация статического сайта, API и медиа.
- `docs` — описание стека, функционала и интеграций.
- `tools` — локальная автоматическая проверка ссылок и JavaScript.
- `archive/legacy-root` — резервные серверные копии; код оттуда не исполняется.

## Асинхронная загрузка

`public/assets/js/core/async-state.js` предоставляет единые операции `single`, `latest`, `serial`, `invalidate` и `waitFor`. `auth.js` предоставляет `whenReady()` и `requireClient()`. Модули данных и настроек ожидают готовность клиента, а редакторы игнорируют повторный `boot()` для того же пользователя. Это предотвращает очистку формы при обновлении токена, возврате во вкладку и одновременном приходе нескольких ответов.

## Проверка

Из корня проекта выполняется:

```text
npm run check
```

Команда не устанавливает зависимости. Она проверяет существование локальных `src`/`href`, синтаксис всех собственных JavaScript-файлов и inline-скриптов HTML.
